1. Mục Đích & Ý Nghĩa "Why Lại Có"

Trong cuốn sách nổi tiếng của Daniel Kahneman, tư duy con người chia làm 2 hệ thống: System 1 (nhanh, trực giác, phản xạ chớp nhoáng) và System 2 (chậm, logic, suy luận sâu).

Làn sóng AI hiện nay (như OpenAI o1/o3) dồn toàn lực cho System 2 — suy nghĩ từng token mất 5–60 giây. Nhưng trong sản phẩm phần mềm thực tế, hơn 80% tác vụ chỉ là phân loại, định tuyến, bắt lỗi hoặc kiểm duyệt:

  • Vấn đề của LLM truyền thống: Quá chậm (2–5 giây), đắt đỏ ($5–$30/M token), dễ vỡ cấu trúc JSON (hallucination), và xác suất tự tin thường là "ảo" (uncalibrated).
  • Sự ra đời của Jev: Loại bỏ hoàn toàn tính năng chat và sinh văn bản tự do. Thay vào đó, nó hoạt động như một "câu lệnh IF thông minh định kiểu tĩnh" được nhúng trực tiếp vào codebase.

2. Cơ Chế Hoạt Động Cốt Lõi (Architecture)

  • Non-Autoregressive & Parallel Sampler: Không sinh từng token nối tiếp nhau. Xử lý toàn bộ context đầu vào trong 1 lượt duy nhất (Single-pass) qua mạng nơ-ron, trả kết quả chỉ sau 70–300ms.
  • 3 Dạng Typed Queries duy nhất:
    • choice: Chọn nhãn tối ưu trong danh sách tùy biến kèm điểm xác suất thực tế.
    • score: Chấm điểm liên tục trên thang đo định nghĩa (ví dụ: urgency 1–10).
    • null (Boolean): Câu hỏi Có/Không (Binary True/False).
  • Thuật toán RLCD (RL for Calibrated Decisions): Phát minh của Diogo Almeida. Đảm bảo nếu model nói "Confidence 0.85" thì trong 100 lần, nó thực sự chính xác đúng 85 lần — biến điểm số thành căn cứ toán học vững chắc cho code rẽ nhánh an toàn.

4. Cách Ứng Dụng Trong Hệ Thống Phần Mềm Thực Tế

Trong video, Sam Witteveen minh họa Jev như một hàm logic trong code. Thay vì dùng regex thô sơ hoặc gọi API OpenAI tốn kém, ta tích hợp Jev làm tầng lọc đầu tiên:

// Ví dụ mô phỏng tích hợp Jev trong hệ thống chăm sóc khách hàng: const evaluation = await jev.evaluate({ input: customerTicketText, query: { type: "choice", options: ["billing_dispute", "technical_bug", "feature_request", "spam"] } }); // Nhờ thuật toán RLCD, confidence là số đo thống kê đáng tin cậy: if (evaluation.confidence >= 0.90) { // Đường rẽ tốc độ cao: 70ms - tự động chuyển thẳng phòng ban autoRouteTicket(evaluation.bestChoice); } else if (evaluation.confidence >= 0.60) { // Bất định nhẹ: Chuyển sang mô hình System 2 (GPT-4o) phân tích sâu callReasoningLLM(customerTicketText); } else { // Độ tin cậy thấp: Chuyển chuyên viên con người kiểm tra escalateToHumanSupport(customerTicketText); }
Support & Triage

Phân loại hàng triệu ticket trong chớp mắt, gắn nhãn phòng ban và mức độ khẩn cấp (Urgency score).

RAG Reranking

Chấm điểm độ liên quan giữa câu hỏi và các đoạn chunk tài liệu trong 70ms trước khi đưa vào ngữ cảnh LLM.

Guardrails & Security

Kiểm duyệt prompt injection, ngôn từ độc hại và rò rỉ dữ liệu nhạy cảm trước khi dữ liệu đi vào mạng nội bộ.
