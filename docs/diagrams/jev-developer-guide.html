Hướng Dẫn Chi Tiết: Sử Dụng & Ứng Dụng Jev

Cẩm nang kỹ thuật thực hành toàn diện về mô hình phân loại System 1 Jev (TypeSafe AI): Cú pháp SDK Python/TypeScript, 3 kiểu câu hỏi nguyên thủy (Choice, Score, Noul), cơ chế song song hóa đa câu hỏi trong một pass duy nhất và 4 mẫu kiến trúc triển khai thực tế.

1. Ba Kiểu Câu Hỏi Nguyên Thủy (Core Primitives) Của Jev

Jev không nhận câu hỏi mở dạng chat, mà bắt buộc mọi câu hỏi phải thuộc 1 trong 3 kiểu định dạng cấu trúc sau:

Choice(instructions, criteria)

Mục đích: Chọn 1 nhãn chính xác từ danh sách các lựa chọn (hỗ trợ tối đa 255 nhãn).

Đầu ra: .choice (nhãn thắng cuộc), .probabilities (phân phối xác suất từng nhãn), và .confidence.

Choice( instructions="Phân loại ticket khách hàng", criteria={ "billing": "Hóa đơn, hoàn tiền, thanh toán", "technical": "Lỗi crash, bug ứng dụng", "feature": "Yêu cầu tính năng mới" } )
Score(instructions, criteria)

Mục đích: Chấm điểm mức độ trên một thang đo thứ tự định nghĩa trước (từ 2 đến 10 cấp độ).

Đầu ra: .score (số thực liên tục, ví dụ 2.4/3.0 phản ánh mức độ nội suy toán học giữa các mốc).

Score( instructions="Đánh giá mức độ khẩn cấp", criteria=["thấp", "trung_bình", "khẩn_cấp"] )
Noul(instructions)

Mục đích: Đánh giá một nhận định Đúng hay Sai (Boolean Question).

Đầu ra: .noul (số thực từ 0.0 đến 1.0 phản ánh xác suất nhận định đó là ĐÚNG).

Noul( instructions="Khách hàng có đang đe dọa rời bỏ dịch vụ (churn) không?" )

2. Code Mẫu: Tích Hợp Bằng Python SDK

Cài đặt thư viện chính thức:

pip install typesafe-sdk
import os from typesafe_sdk import TypeSafeClient, Choice, Score, Noul # Khởi tạo client (tự động nhận TYPESAFE_API_KEY) client = TypeSafeClient() customer_text = """ Tôi vừa bị trừ tiền 2 lần cho đơn hàng #9821! Yêu cầu hoàn lại tiền ngay lập tức, nếu không tôi sẽ hủy tài khoản! """ # Gọi Jev đánh giá song song 3 câu hỏi chỉ trong 1 forward pass (~120ms) response = client.system_one( state=customer_text, questions={ "dept": Choice( instructions="Chuyển ticket này về bộ phận nào?", criteria={ "billing": "Hóa đơn và hoàn tiền", "tech_support": "Hỗ trợ kỹ thuật phần mềm" } ), "urgency": Score( instructions="Đo lường mức độ khẩn cấp của khách hàng", criteria=["low", "medium", "high", "critical"] ), "churn_threat": Noul( instructions="Khách hàng có ý định hủy gói/tẩy chay dịch vụ?" ) } ) # Truy xuất kết quả có định kiểu (Type-safe) print(f"Phòng ban: {response.answers['dept'].choice}") # 'billing' print(f"Mức khẩn cấp: {response.answers['urgency'].score}") # 3.8 print(f"Xác suất churn: {response.answers['churn_threat'].noul}") # 0.96

3. Gọi Bằng cURL Hoặc TypeScript API

Gửi HTTP POST trực tiếp đến cổng API của TypeSafe:

curl -X POST https://api.typesafe.ai/v1/systemone \ -H "Authorization: Bearer $TYPESAFE_API_KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "jev-latest", "state": "Tôi bị trừ tiền 2 lần cho đơn hàng #9821...", "questions": { "dept": { "type": "choice", "instructions": "Chuyển ticket về phòng ban nào?", "criteria": { "billing": "Hóa đơn và hoàn tiền", "tech_support": "Hỗ trợ kỹ thuật" } }, "urgency": { "type": "score", "instructions": "Mức độ khẩn cấp", "criteria": ["low", "medium", "high", "critical"] }, "churn_threat": { "type": "noul", "instructions": "Khách hàng có dọa hủy dịch vụ không?" } } }'

Đặc điểm kinh tế: Giá tính theo token đầu vào ($0.042/triệu tokens). Toàn bộ dữ liệu JSON trả về (output) được miễn phí 100%.

4. Bốn Mẫu Ứng Dụng Thực Tế Trong Kiến Trúc AI Hiện Đại

Mẫu 1: RAG Semantic Reranker Siêu Tốc

Khi tìm kiếm ngữ nghĩa (vector search) trả về 50 đoạn văn bản (chunks), thay vì dùng Cross-Encoder nặng nề hoặc LLM sinh văn bản, ta truyền từng chunk vào Jev với câu hỏi Score("Mức độ liên quan để trả lời câu hỏi X", ["không liên quan", "liên quan một phần", "rất liên quan"]). Jev rerank 50 chunks chỉ trong ~200ms với chi phí gần như bằng 0.

Mẫu 2: Tường Lửa Bảo Mật & Guardrails Cho Agent

Trước khi gửi prompt của người dùng vào mô hình lớn (GPT-4o/Claude), cho qua Jev với câu hỏi Noul("Người dùng có đang cố ý thực hiện Jailbreak / Prompt Injection không?"). Vì độ trễ chỉ 70ms, nó trở thành một "bước kiểm tra tức thì" mà người dùng không hề cảm nhận thấy độ chậm.

Mẫu 3: Dynamic Tool Router (Bộ Điều Hướng Agent)

Trong hệ thống Multi-Agent, việc quyết định bước tiếp theo nên gọi API nào thường được giao cho LLM lớn thông qua Function Calling (rất tốn kém). Sử dụng Jev Choice("Nên dùng công cụ nào?", { "db_search": "...", "send_email": "..." }) giúp router chuyển nhánh ngay lập tức.

Mẫu 4: Phân Luồng Ngưỡng RLCD (Tri-State Decision)

Dựa trên điểm tin cậy toán học thực tế của thuật toán RLCD: nếu confidence ≥ 0.90 → Auto-execute; nếu 0.60 ≤ confidence < 0.90 → Gọi System 2 LLM (o1/Claude) suy luận sâu; nếu confidence < 0.60 → Chuyển cho con người duyệt thủ công. Tiết kiệm 85% chi phí vận hành toàn hệ thống.
